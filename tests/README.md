# 테스트 (앱과 별개)

`index.html`의 계산이 맞는지 확인하는 테스트예요. 앱 동작과는 상관없고, 지워도 앱은 그대로 돌아요.
규칙과 확인할 불변식은 저장소의 `CLAUDE.md` 7장에 있어요.

## 돌리는 법

```bash
cd tests
npm install        # jsdom 설치 (처음 한 번)
./run.sh           # 전부 돌리기 (20분쯤). 결과 자세한 내용은 tests/out/
./syn.sh           # 문법 검사만
node t/skip.js     # 묶음 하나만
./same.sh          # 계산 정리용: 정리 전(v4.10)과 결과가 100% 같은지 (9분쯤, 아래 참고)
```

다른 파일을 검사하려면 `FC_HTML=/경로/파일.html ./run.sh`처럼 써요.

## 구성

| 위치 | 내용 |
|---|---|
| `t/h.js` | 하네스. jsdom으로 앱을 띄우고 가짜 시계로 하루씩 넘기며 실제 버튼을 눌러요 |
| `t/seed.js` | 테스트용 목표들 (강의·양·난이도·페이지, 마감일 기준·하루 가능 시간 기준, 개수 기준) |
| `t/lib.js` | 공통 도구: 불변식 검사(`inv`), 계획대로 따라가기(`follow`) |
| `t/baseline.js`, `t/baseline2.js` | 새 기능을 안 쓰는 목표가 v4.7과 똑같이 계산되는지 비교하는 시나리오 (`baseline/`의 v4.7 결과와 비교) |
| `t/ext*.js` | 따로 할 것(복습 추가) |
| `t/skip*.js`, `t/skipcur*.js` | 챕터 건너뛰기 |
| `t/yday*.js` | 어제 체크, "안 했어요" |
| `t/pin*.js` | 오늘·내일 양 정하기 |
| `r/` | 독립 재검토에서 만든 스크립트. `f_fuzz2.js`(복습 무작위), `s_fuzz.js`(건너뛰기 무작위), `o_twins.js`·`yd_twins.js`(쌍둥이 비교)가 핵심이고, 나머지는 그때그때 찾은 버그의 재현 스크립트예요 |
| `t/trace.js`, `t/same.js`, `same.sh` | 계산 정리용 "100% 같은가" 비교 (아래) |
| `baseline/` | v4.7이 낸 결과(압축)와, 계산 정리 전(v4.10)의 기록 `v410-trace.json.gz`. 바꾸지 않아요 |

## 계산 정리용 비교 (`same.sh`)

계산 코드를 정리(리팩터링)할 때 "화면과 결과가 정리 전과 100% 같은지" 확인하는 도구예요 (`CLAUDE.md` 11장).

- `t/trace.js`가 앱을 무작위로(하지만 매번 똑같이) 써요: 체크, 덜/더 하기, 미루기(마감일까지·이번 주 안에), 어제 체크·안 했어요,
  수정(마감일·요일·하루 양·끝 번호…), 복습 추가·지우기, 건너뛰기·되살리기, 양 정하기, 쉬는 날, 요일 비율, 일시중단, ↻ 등.
  목표는 개수·강의·양·난이도·페이지(복습·건너뛰기 포함), 마감일 기준·하루 가능 시간 기준이 섞여 나와요.
- 매일 아침·저녁에 앱이 계산한 것을 전부 기록해요: 저장된 데이터, 목표별 계획 전체(모든 행·상태·밀림·하루 양·주간 목표·어제 칸·미루기 미리보기),
  화면 글자. 기록은 짧은 해시로 남겨요. (계획·행 안의 키 순서는 보지 않아요. 값이 `undefined`인 키가 있는지는 봐요.)
- `baseline/v410-trace.json.gz`는 정리 전 버전(v4.10, 커밋 `0e1cf46`)으로 뜬 기록이에요(시나리오 80개 × 60시점).
  `./same.sh`는 지금 파일로 같은 기록을 떠서 비교해요. **차이가 0이어야 해요.**

```bash
./same.sh          # 80개 전부 (9분쯤)
./same.sh 16       # 앞의 16개만 (작업 중 빠른 확인, 2분)
./same.sh why 7    # 7번 시나리오에서 뭐가 다른지 자세히 (git에서 v4.10 파일을 꺼내 비교)
```

- 계산을 **일부러** 바꾼 경우(버그 수정 등)에만 기준을 다시 떠요: 바뀐 내용을 `./same.sh why`로 확인하고 사용자에게 설명한 뒤 `./same.sh make`.
- 기록기 자체(`t/trace.js`, `t/h.js`, `r/pin_lib.js`, `r/common.js`, `t/seed.js`)를 고치면 기준과 비교할 수 없게 돼요(그렇게 알려줘요).
  그때는 정리 전 파일로 기준을 다시 떠요: `git show 0e1cf46:index.html > out/ref.html && FC_HTML=out/ref.html ./same.sh make`
  (그 사이에 계산을 일부러 바꾼 적이 있으면, 그 버전의 파일로 떠요.)

## 새 기준 결과를 만들 때

계산을 일부러 바꾼 게 아니라면 `baseline/`은 건드리지 않아요. 예전 버전 파일이 필요하면 git에서 꺼내요.

```bash
git show <커밋>:index.html > out/old.html
node t/baseline.js out/old.html > out/old.json
```
